Bab 01

Pengertian & Konsep Dasar OOP

Object-Oriented Programming (OOP) adalah paradigma pemrograman yang mengorganisir kode berdasarkan konsep objek — bukan berdasarkan fungsi atau logika prosedural.

Di ABAP, OOP diperkenalkan sejak ABAP Objects (SAP NetWeaver 6.10+). SAP sendiri secara agresif mendorong penggunaan OOP, terutama untuk:

  • Enhancement Framework
  • BAdI (Business Add-Ins)
  • ABAP CDS Views
  • SAP Fiori / RAP (RESTful ABAP Programming)

4 Pilar Utama OOP

Pilar Penjelasan
Encapsulation Menyembunyikan detail internal, hanya menampilkan yang perlu
Inheritance Pewarisan sifat dan perilaku dari class parent ke child
Polymorphism Satu interface, banyak implementasi berbeda
Abstraction Menyederhanakan kompleksitas dengan menyembunyikan detail

Perbedaan ABAP Procedural vs OOP

ABAP Procedural ABAP OOP
Subroutines (FORM) Methods
Function Modules Classes & Objects
Global variables Attributes (instance/static)
Top-Down approach Object-based modeling
Sulit reuse Mudah reuse & extend
Bab 02

Class & Object

Analogi

Class = "Mobil" (desain di kertas / blueprint)

Object = "Avanza merah B 1234 CD" (mobil nyata di jalan)

Struktur Class di ABAP

*----------------------------------------------------------------------*
* CLASS DEFINITION (Deklarasi — apa yang dimiliki class)
*----------------------------------------------------------------------*
CLASS lcl_vehicle DEFINITION.
  PUBLIC SECTION.
    " Attributes (data)
    DATA: mv_brand  TYPE string,
          mv_color  TYPE string,
          mv_speed  TYPE i.

    " Methods (behavior)
    METHODS: constructor
               IMPORTING iv_brand TYPE string
                         iv_color TYPE string,
             accelerate
               IMPORTING iv_increment TYPE i,
             get_info
               RETURNING VALUE(rv_info) TYPE string.
ENDCLASS.

*----------------------------------------------------------------------*
* CLASS IMPLEMENTATION (Realisasi — bagaimana cara kerjanya)
*----------------------------------------------------------------------*
CLASS lcl_vehicle IMPLEMENTATION.

  METHOD constructor.
    mv_brand = iv_brand.
    mv_color = iv_color.
    mv_speed = 0.
  ENDMETHOD.

  METHOD accelerate.
    mv_speed = mv_speed + iv_increment.
  ENDMETHOD.

  METHOD get_info.
    rv_info = |{ mv_brand } { mv_color } - Kecepatan: { mv_speed } km/jam|.
  ENDMETHOD.

ENDCLASS.

*----------------------------------------------------------------------*
* PROGRAM UTAMA — Membuat Object
*----------------------------------------------------------------------*
START-OF-SELECTION.

  " Membuat instance (object) dari class
  DATA(lo_car1) = NEW lcl_vehicle( iv_brand = 'Toyota'
                                     iv_color = 'Merah' ).

  DATA(lo_car2) = NEW lcl_vehicle( iv_brand = 'Honda'
                                     iv_color = 'Hitam' ).

  " Memanggil method
  lo_car1->accelerate( 60 ).
  lo_car1->accelerate( 40 ).
  lo_car2->accelerate( 80 ).

  WRITE: / lo_car1->get_info( ).
  " Output: Toyota Merah - Kecepatan: 100 km/jam

  WRITE: / lo_car2->get_info( ).
  " Output: Honda Hitam - Kecepatan: 80 km/jam

Penjelasan Syntax

Syntax Penjelasan
CLASS ... DEFINITION Deklarasi class (header)
CLASS ... IMPLEMENTATION Implementasi method (body)
DATA: Instance attribute (tiap objek punya sendiri)
CLASS-DATA: Static attribute (satu untuk semua objek)
METHODS: Deklarasi method
CONSTRUCTOR Method khusus yang otomatis dipanggil saat object dibuat
NEW lcl_class( ) Membuat instance baru (ABAP 7.40+)
-> Operator untuk akses member dari instance
Bab 03

Visibility (Access Modifiers)

ABAP memiliki 3 level visibility yang menentukan dari mana suatu attribute atau method bisa diakses:

Level Akses
PUBLIC SECTION Bisa diakses dari manapun
PROTECTED SECTION Bisa diakses dari class ini & class turunannya
PRIVATE SECTION Hanya bisa diakses dari dalam class itu sendiri

Contoh

CLASS lcl_employee DEFINITION.
  PUBLIC SECTION.
    METHODS: constructor
               IMPORTING iv_name   TYPE string
                         iv_salary TYPE p,
             get_display_info
               RETURNING VALUE(rv_info) TYPE string.

  PROTECTED SECTION.
    DATA: mv_department TYPE string.
    " ↑ Hanya class turunan yang bisa akses

  PRIVATE SECTION.
    DATA: mv_name   TYPE string,
          mv_salary TYPE p.
    " ↑ Tidak bisa diakses dari luar class
ENDCLASS.

CLASS lcl_employee IMPLEMENTATION.
  METHOD constructor.
    mv_name   = iv_name.
    mv_salary = iv_salary.
    mv_department = 'General'.
  ENDMETHOD.

  METHOD get_display_info.
    rv_info = |{ mv_name } - Dept: { mv_department } - Gaji: { mv_salary }|.
  ENDMETHOD.
ENDCLASS.

START-OF-SELECTION.
  DATA(lo_emp) = NEW lcl_employee(
    iv_name = 'Budi' iv_salary = 5000000 ).

  WRITE: / lo_emp->get_display_info( ).

  " lo_emp->mv_name = 'Andi'.       " ❌ COMPILE ERROR — PRIVATE
  " lo_emp->mv_salary = 6000000.    " ❌ COMPILE ERROR — PRIVATE
  " lo_emp->mv_department = 'IT'.   " ❌ COMPILE ERROR — PROTECTED
Bab 04

Constructor

Instance Constructor

Dipanggil otomatis saat object dibuat dengan NEW atau CREATE OBJECT.

CLASS lcl_product DEFINITION.
  PUBLIC SECTION.
    DATA: mv_name  TYPE string,
          mv_price TYPE p LENGTH 8 DECIMALS 2.

    METHODS constructor
      IMPORTING iv_name  TYPE string
                iv_price TYPE p.
ENDCLASS.

CLASS lcl_product IMPLEMENTATION.
  METHOD constructor.
    mv_name  = iv_name.
    mv_price = iv_price.
    WRITE: / |Product "{ mv_name }" dibuat dengan harga { mv_price }|.
  ENDMETHOD.
ENDCLASS.

START-OF-SELECTION.
  " Constructor langsung dipanggil saat NEW
  DATA(lo_prod) = NEW lcl_product(
    iv_name = 'Laptop' iv_price = 15000000 ).
  " Output: Product "Laptop" dibuat dengan harga 15000000

Static Constructor (CLASS_CONSTRUCTOR)

Dipanggil hanya sekali otomatis saat class pertama kali diakses dalam program.

CLASS lcl_config DEFINITION.
  PUBLIC SECTION.
    CLASS-DATA: gv_system_name TYPE string.
    CLASS-METHODS: class_constructor.
ENDCLASS.

CLASS lcl_config IMPLEMENTATION.
  METHOD class_constructor.
    gv_system_name = 'SAP Production System'.
    WRITE: / 'Static constructor dipanggil — hanya sekali!'.
  ENDMETHOD.
ENDCLASS.

START-OF-SELECTION.
  " Pertama kali akses → class_constructor otomatis jalan
  WRITE: / lcl_config=>gv_system_name.

  " Kedua kali → class_constructor TIDAK dipanggil lagi
  WRITE: / lcl_config=>gv_system_name.
Bab 05

Static vs Instance Members

Instance Member Static Member
Dimiliki per OBJECT Dimiliki oleh CLASS (satu untuk semua)
DATA: / METHODS: CLASS-DATA: / CLASS-METHODS:
Akses: lo_obj->member Akses: lcl_class=>member

Contoh

CLASS lcl_counter DEFINITION.
  PUBLIC SECTION.
    " Instance — tiap object punya counter sendiri
    DATA: mv_count TYPE i.

    " Static — semua object share total
    CLASS-DATA: gv_total_objects TYPE i.

    METHODS: constructor, increment.
    CLASS-METHODS: get_total_objects
                    RETURNING VALUE(rv_total) TYPE i.
ENDCLASS.

CLASS lcl_counter IMPLEMENTATION.
  METHOD constructor.
    mv_count = 0.
    gv_total_objects = gv_total_objects + 1.
  ENDMETHOD.

  METHOD increment.
    mv_count = mv_count + 1.
  ENDMETHOD.

  METHOD get_total_objects.
    rv_total = gv_total_objects.
  ENDMETHOD.
ENDCLASS.

START-OF-SELECTION.
  DATA(lo_c1) = NEW lcl_counter( ).
  DATA(lo_c2) = NEW lcl_counter( ).
  DATA(lo_c3) = NEW lcl_counter( ).

  lo_c1->increment( ). lo_c1->increment( ).
  lo_c2->increment( ).

  WRITE: / |Counter 1: { lo_c1->mv_count }|.    " 2
  WRITE: / |Counter 2: { lo_c2->mv_count }|.    " 1
  WRITE: / |Counter 3: { lo_c3->mv_count }|.    " 0

  " Static — akses via class name (=>)
  WRITE: / |Total objects: { lcl_counter=>get_total_objects( ) }|.
  " Output: 3
Bab 06

Inheritance (Pewarisan)

┌──────────────┐ │ lcl_vehicle │ ← Parent / Superclass └──────┬───────┘ │ INHERITS FROM ┌───────┴────────┐ │ │ ┌──────┴─────┐ ┌──────┴────────┐ │ lcl_car │ │ lcl_motorcycle│ ← Child / Subclass └────────────┘ └───────────────┘

Contoh Lengkap

*----------------------------------------------------------------------*
* PARENT CLASS
*----------------------------------------------------------------------*
CLASS lcl_vehicle DEFINITION.
  PUBLIC SECTION.
    DATA: mv_brand TYPE string,
          mv_speed TYPE i.
    METHODS: constructor IMPORTING iv_brand TYPE string,
             accelerate  IMPORTING iv_increment TYPE i,
             brake,
             get_status  RETURNING VALUE(rv_status) TYPE string.
ENDCLASS.

CLASS lcl_vehicle IMPLEMENTATION.
  METHOD constructor.
    mv_brand = iv_brand. mv_speed = 0.
  ENDMETHOD.
  METHOD accelerate.
    mv_speed = mv_speed + iv_increment.
  ENDMETHOD.
  METHOD brake.
    mv_speed = 0.
  ENDMETHOD.
  METHOD get_status.
    rv_status = |{ mv_brand } — { mv_speed } km/jam|.
  ENDMETHOD.
ENDCLASS.

*----------------------------------------------------------------------*
* CHILD CLASS — Car (dengan REDEFINITION)
*----------------------------------------------------------------------*
CLASS lcl_car DEFINITION INHERITING FROM lcl_vehicle.
  PUBLIC SECTION.
    DATA: mv_num_doors TYPE i.
    METHODS: constructor
               IMPORTING iv_brand     TYPE string
                         iv_num_doors TYPE i,
             get_status REDEFINITION.
ENDCLASS.

CLASS lcl_car IMPLEMENTATION.
  METHOD constructor.
    super->constructor( iv_brand ).  " ← Panggil parent
    mv_num_doors = iv_num_doors.
  ENDMETHOD.

  METHOD get_status.  " ← Override parent method
    rv_status = |{ mv_brand } ({ mv_num_doors } pintu) — { mv_speed } km/jam|.
  ENDMETHOD.
ENDCLASS.

*----------------------------------------------------------------------*
* MAIN PROGRAM
*----------------------------------------------------------------------*
START-OF-SELECTION.
  DATA(lo_car) = NEW lcl_car(
    iv_brand = 'Toyota' iv_num_doors = 4 ).

  lo_car->accelerate( 120 ).       " ← Method warisan dari parent
  WRITE: / lo_car->get_status( ).  " ← Versi override (child)
  " Output: Toyota (4 pintu) — 120 km/jam

  lo_car->brake( ).                 " ← Method warisan dari parent
  WRITE: / lo_car->get_status( ).
  " Output: Toyota (4 pintu) — 0 km/jam

Keyword Penting Inheritance

Keyword Fungsi
INHERITS FROM Menentukan parent class
super-> Memanggil method / constructor parent
REDEFINITION Override method parent di child class
Bab 07

Polymorphism

Polymorphism = satu nama method, banyak perilaku berbeda tergantung object-nya. Kompiler akan memanggil versi method yang sesuai dengan tipe object sebenarnya.

Contoh: Sistem Hitung Luas Bangun Datar

*----------------------------------------------------------------------*
* PARENT — Shape
*----------------------------------------------------------------------*
CLASS lcl_shape DEFINITION.
  PUBLIC SECTION.
    DATA: mv_name TYPE string.
    METHODS: constructor IMPORTING iv_name TYPE string,
             get_area    RETURNING VALUE(rv_area) TYPE f.
ENDCLASS.

CLASS lcl_shape IMPLEMENTATION.
  METHOD constructor. mv_name = iv_name. ENDMETHOD.
  METHOD get_area. rv_area = 0. ENDMETHOD.
ENDCLASS.

*----------------------------------------------------------------------*
* CHILD — Circle
*----------------------------------------------------------------------*
CLASS lcl_circle DEFINITION INHERITING FROM lcl_shape.
  PUBLIC SECTION.
    DATA: mv_radius TYPE f.
    METHODS: constructor IMPORTING iv_radius TYPE f,
             get_area REDEFINITION.
ENDCLASS.

CLASS lcl_circle IMPLEMENTATION.
  METHOD constructor.
    super->constructor( 'Lingkaran' ). mv_radius = iv_radius.
  ENDMETHOD.
  METHOD get_area.
    rv_area = '3.14159' * mv_radius * mv_radius.
  ENDMETHOD.
ENDCLASS.

*----------------------------------------------------------------------*
* CHILD — Rectangle
*----------------------------------------------------------------------*
CLASS lcl_rectangle DEFINITION INHERITING FROM lcl_shape.
  PUBLIC SECTION.
    DATA: mv_width TYPE f, mv_height TYPE f.
    METHODS: constructor IMPORTING iv_width TYPE f iv_height TYPE f,
             get_area REDEFINITION.
ENDCLASS.

CLASS lcl_rectangle IMPLEMENTATION.
  METHOD constructor.
    super->constructor( 'Persegi Panjang' ).
    mv_width = iv_width. mv_height = iv_height.
  ENDMETHOD.
  METHOD get_area. rv_area = mv_width * mv_height. ENDMETHOD.
ENDCLASS.

*----------------------------------------------------------------------*
* MAIN — Polymorphism in action!
*----------------------------------------------------------------------*
START-OF-SELECTION.

  " Tipe: REF TO lcl_shape (parent)
  " Isi  : berbagai child object
  DATA: lt_shapes TYPE TABLE OF REF TO lcl_shape.

  APPEND NEW lcl_circle( '7.0' ) TO lt_shapes.
  APPEND NEW lcl_rectangle(
    iv_width = '5.0' iv_height = '3.0' ) TO lt_shapes.

  " Satu loop, satu method name → hasil BERBEDA
  LOOP AT lt_shapes INTO DATA(lo_shape).
    WRITE: / |{ lo_shape->mv_name }: 
            Luas = { lo_shape->get_area( ) DECIMALS = 2 }|.
  ENDLOOP.
  " Output:
  " Lingkaran: Luas = 153.94
  " Persegi Panjang: Luas = 15.00
Key Insight

Kompiler memanggil get_area() milik masing-masing child class, bukan parent. Inilah yang disebut polymorphism — satu nama method, banyak implementasi.

Bab 08

Interface

Interface mendefinisikan kontrak — semua class yang mengimplementasikannya wajib menyediakan method-method yang didefinisikan di interface.

┌─────────────┐ │ lif_printable│ ← Interface (kontrak) │ + print() │ └──────┬──────┘ │ IMPLEMENTS ┌────┴──────────────┐ │ │ ┌─┴───────────┐ ┌───┴──────────┐ │ lcl_invoice │ │ lcl_report │ ← Wajib implement print() └─────────────┘ └──────────────┘

Contoh

*----------------------------------------------------------------------*
* INTERFACE DEFINITION
*----------------------------------------------------------------------*
INTERFACE lif_printable.
  METHODS: print RETURNING VALUE(rv_output) TYPE string.
ENDINTERFACE.

INTERFACE lif_emailable.
  METHODS: send_email IMPORTING iv_to TYPE string
                      RETURNING VALUE(rv_success) TYPE abap_bool.
ENDINTERFACE.

*----------------------------------------------------------------------*
* CLASS: Invoice — implements BOTH interfaces
*----------------------------------------------------------------------*
CLASS lcl_invoice DEFINITION.
  PUBLIC SECTION.
    INTERFACES: lif_printable, lif_emailable.
    DATA: mv_invoice_no TYPE string,
          mv_amount     TYPE p LENGTH 10 DECIMALS 2.
    METHODS constructor
      IMPORTING iv_invoice_no TYPE string
                iv_amount     TYPE p.
ENDCLASS.

CLASS lcl_invoice IMPLEMENTATION.
  METHOD constructor.
    mv_invoice_no = iv_invoice_no.
    mv_amount     = iv_amount.
  ENDMETHOD.

  METHOD lif_printable~print.
    rv_output = |Invoice #{ mv_invoice_no }: Rp { mv_amount }|.
  ENDMETHOD.

  METHOD lif_emailable~send_email.
    rv_success = abap_true.
    WRITE: / |Invoice #{ mv_invoice_no } dikirim ke { iv_to }|.
  ENDMETHOD.
ENDCLASS.

*----------------------------------------------------------------------*
* MAIN — Polymorphism via interface type
*----------------------------------------------------------------------*
START-OF-SELECTION.

  DATA: lt_printables TYPE TABLE OF REF TO lif_printable.

  APPEND NEW lcl_invoice(
    iv_invoice_no = 'INV-001'
    iv_amount = 1500000 ) TO lt_printables.

  LOOP AT lt_printables INTO DATA(lo_p).
    WRITE: / lo_p->print( ).
  ENDLOOP.
  " Output: Invoice #INV-001: Rp 1500000.00

  " Akses method interface spesifik
  DATA(lo_inv) = NEW lcl_invoice(
    iv_invoice_no = 'INV-002' iv_amount = 2500000 ).
  lo_inv->lif_emailable~send_email( 'mgr@company.com' ).
Bab 09

Abstract Class & Method

  • Abstract class: Tidak bisa dibuat object-nya langsung, hanya bisa di-inherit.
  • Abstract method: Tidak punya implementasi di parent — child wajib mengimplementasikannya.
CLASS lcl_shape DEFINITION ABSTRACT.
  PUBLIC SECTION.
    DATA: mv_name TYPE string.
    METHODS: constructor IMPORTING iv_name TYPE string,
             get_area ABSTRACT
               RETURNING VALUE(rv_area) TYPE f,
             describe RETURNING VALUE(rv_desc) TYPE string.
ENDCLASS.

CLASS lcl_shape IMPLEMENTATION.
  METHOD constructor. mv_name = iv_name. ENDMETHOD.
  METHOD describe.
    rv_desc = |{ mv_name } memiliki luas { get_area( ) DECIMALS = 2 }|.
  ENDMETHOD.
ENDCLASS.

*----------------------------------------------------------------------*
* CHILD: wajib implement get_area()
*----------------------------------------------------------------------*
CLASS lcl_square DEFINITION INHERITING FROM lcl_shape.
  PUBLIC SECTION.
    DATA: mv_side TYPE f.
    METHODS: constructor IMPORTING iv_side TYPE f,
             get_area REDEFINITION.
ENDCLASS.

CLASS lcl_square IMPLEMENTATION.
  METHOD constructor.
    super->constructor( 'Persegi' ). mv_side = iv_side.
  ENDMETHOD.
  METHOD get_area. rv_area = mv_side * mv_side. ENDMETHOD.
ENDCLASS.

START-OF-SELECTION.
  " DATA(lo) = NEW lcl_shape( ).  " ❌ ERROR — abstract
  DATA(lo_sq) = NEW lcl_square( '5.0' ).
  WRITE: / lo_sq->describe( ).
  " Output: Persegi memiliki luas 25.00
Perhatian

Jika child class tidak mengimplementasikan method abstract, akan terjadi compile error. Ini memastikan semua subclass memiliki perilaku minimum yang dibutuhkan.

Bab 10

Events

Event memungkinkan satu class memberi tahu class lain bahwa sesuatu telah terjadi, tanpa perlu tahu siapa yang mendengarkan. Ini disebut publisher-subscriber pattern.

*----------------------------------------------------------------------*
* PUBLISHER — Yang mengirim event
*----------------------------------------------------------------------*
CLASS lcl_order DEFINITION.
  PUBLIC SECTION.
    DATA: mv_order_id TYPE string,
          mv_status   TYPE string.

    " Deklarasi event
    EVENTS: order_created
              EXPORTING VALUE(ev_order_id) TYPE string,
              order_completed
              EXPORTING VALUE(ev_order_id) TYPE string.

    METHODS: constructor IMPORTING iv_order_id TYPE string,
             process_order.
ENDCLASS.

CLASS lcl_order IMPLEMENTATION.
  METHOD constructor.
    mv_order_id = iv_order_id.
    mv_status   = 'New'.
  ENDMETHOD.

  METHOD process_order.
    mv_status = 'Processing'.
    WRITE: / |Order { mv_order_id } sedang diproses...|.

    " RAISE EVENT — kirim sinyal ke semua listener
    RAISE EVENT order_created
      EXPORTING ev_order_id = mv_order_id.

    mv_status = 'Completed'.
    RAISE EVENT order_completed
      EXPORTING ev_order_id = mv_order_id.
  ENDMETHOD.
ENDCLASS.

*----------------------------------------------------------------------*
* SUBSCRIBER — Yang mendengarkan event
*----------------------------------------------------------------------*
CLASS lcl_notifier DEFINITION.
  PUBLIC SECTION.
    METHODS:
      on_created FOR EVENT order_created OF lcl_order
        IMPORTING ev_order_id,
      on_completed FOR EVENT order_completed OF lcl_order
        IMPORTING ev_order_id.
ENDCLASS.

CLASS lcl_notifier IMPLEMENTATION.
  METHOD on_created.
    WRITE: / |NOTIF: Order { ev_order_id } telah dibuat!|.
  ENDMETHOD.
  METHOD on_completed.
    WRITE: / |NOTIF: Order { ev_order_id } telah selesai!|.
  ENDMETHOD.
ENDCLASS.

*----------------------------------------------------------------------*
* MAIN PROGRAM
*----------------------------------------------------------------------*
START-OF-SELECTION.

  DATA(lo_order)   = NEW lcl_order( 'ORD-001' ).
  DATA(lo_notifier) = NEW lcl_notifier( ).

  " HUBUNGKAN event ke handler (register)
  SET HANDLER lo_notifier->on_created   FOR lo_order.
  SET HANDLER lo_notifier->on_completed FOR lo_order.

  " Proses — event otomatis ter-trigger
  lo_order->process_order( ).

" Output:
" Order ORD-001 sedang diproses...
" NOTIF: Order ORD-001 telah dibuat!
" NOTIF: Order ORD-001 telah selesai!
Bab 11

Friend Class & Singleton Pattern

Friend Class

Ketika class A ingin memberikan akses PRIVATE ke class B:

CLASS lcl_bank_vault DEFINITION FRIENDS lcl_bank_manager.
  PRIVATE SECTION.
    DATA: mv_balance TYPE p LENGTH 12 DECIMALS 2 VALUE 1000000000.
    METHODS: get_balance RETURNING VALUE(rv_bal) TYPE p.
ENDCLASS.

CLASS lcl_bank_vault IMPLEMENTATION.
  METHOD get_balance. rv_bal = mv_balance. ENDMETHOD.
ENDCLASS.

CLASS lcl_bank_manager DEFINITION.
  PUBLIC SECTION.
    METHODS: check_vault RETURNING VALUE(rv_info) TYPE string.
ENDCLASS.

CLASS lcl_bank_manager IMPLEMENTATION.
  METHOD check_vault.
    DATA(lo_vault) = NEW lcl_bank_vault( ).
    " Karena FRIENDS, bisa akses private member:
    rv_info = |Vault: Rp { lo_vault->get_balance( ) }|.
  ENDMETHOD.
ENDCLASS.

Singleton Pattern

Memastikan hanya satu instance yang pernah dibuat:

CLASS lcl_db_connection DEFINITION.
  PUBLIC SECTION.
    CLASS-METHODS: get_instance
      RETURNING VALUE(ro_instance)
        TYPE REF TO lcl_db_connection.
    METHODS: query IMPORTING iv_sql TYPE string
                   RETURNING VALUE(rv_result) TYPE string.
  PRIVATE SECTION.
    CLASS-DATA: go_instance TYPE REF TO lcl_db_connection.
    DATA: mv_connection_id TYPE string.
    METHODS: constructor.
ENDCLASS.

CLASS lcl_db_connection IMPLEMENTATION.
  METHOD constructor.
    mv_connection_id = 'CONN-' && sy-uzeit.
  ENDMETHOD.

  METHOD get_instance.
    IF go_instance IS NOT BOUND.
      go_instance = NEW #( ).
    ENDIF.
    ro_instance = go_instance.
  ENDMETHOD.

  METHOD query.
    rv_result = |Result of "{ iv_sql }" via { mv_connection_id }|.
  ENDMETHOD.
ENDCLASS.

START-OF-SELECTION.
  " Semua variable menunjuk ke instance YANG SAMA
  DATA(lo_db1) = lcl_db_connection=>get_instance( ).
  DATA(lo_db2) = lcl_db_connection=>get_instance( ).

  WRITE: / lo_db1->query( 'SELECT * FROM MARA' ).
  WRITE: / lo_db2->query( 'SELECT * FROM VBAK' ).
  " Keduanya pakai connection_id yang SAMA
Bab 12

Studi Kasus: Sistem Manajemen Karyawan

Requirement

Ada 3 jenis karyawan (Permanent, Contract, Intern) dengan perhitungan gaji berbeda. Sistem harus bisa mencetak payslip, menghitung total payroll, dan mencatat audit. Semua konsep OOP digunakan.

*&---------------------------------------------------------------------*
*& Case Study: HR Management System — OOP ABAP
*&---------------------------------------------------------------------*

*----------------------------------------------------------------------*
* INTERFACES
*----------------------------------------------------------------------*
INTERFACE lif_payable.
  METHODS: calculate_salary RETURNING VALUE(rv_salary) TYPE p,
           get_payslip      RETURNING VALUE(rv_slip) TYPE string.
ENDINTERFACE.

INTERFACE lif_reportable.
  METHODS: generate_report RETURNING VALUE(rv_report) TYPE string.
ENDINTERFACE.

*----------------------------------------------------------------------*
* ABSTRACT BASE CLASS
*----------------------------------------------------------------------*
CLASS lcl_employee DEFINITION ABSTRACT.
  PUBLIC SECTION.
    INTERFACES: lif_payable, lif_reportable.

    ALIASES: calculate_salary FOR lif_payable~calculate_salary,
             get_payslip      FOR lif_payable~get_payslip,
             generate_report  FOR lif_reportable~generate_report.

    CLASS-DATA: gv_total_employees TYPE i,
                gv_total_payroll   TYPE p LENGTH 12 DECIMALS 2.

    DATA: mv_emp_id   TYPE string,
          mv_name     TYPE string,
          mv_base_pay TYPE p LENGTH 10 DECIMALS 2.

    EVENTS: salary_calculated
              EXPORTING VALUE(ev_emp_id) TYPE string
                        VALUE(ev_amount) TYPE p.

    METHODS: constructor
               IMPORTING iv_emp_id   TYPE string
                         iv_name     TYPE string
                         iv_base_pay TYPE p,
             calculate_salary ABSTRACT RETURNING VALUE(rv_salary) TYPE p,
             get_payslip     REDEFINITION,
             generate_report REDEFINITION.

  PROTECTED SECTION.
    METHODS: get_employee_type RETURNING VALUE(rv_type) TYPE string.
ENDCLASS.

CLASS lcl_employee IMPLEMENTATION.
  METHOD constructor.
    mv_emp_id = iv_emp_id.
    mv_name   = iv_name.
    mv_base_pay = iv_base_pay.
    gv_total_employees = gv_total_employees + 1.
  ENDMETHOD.

  METHOD get_payslip.
    DATA(lv_salary) = calculate_salary( ).
    rv_slip = |══════════════════════════════\n| &&
              |  PAYSLIP — { get_employee_type( ) }\n| &&
              |══════════════════════════════\n| &&
              |  ID    : { mv_emp_id }\n| &&
              |  Nama  : { mv_name }\n| &&
              |  Gaji  : Rp { lv_salary }\n| &&
              |══════════════════════════════|.
  ENDMETHOD.

  METHOD generate_report.
    rv_report = |{ mv_emp_id } | { mv_name } | 
                { get_employee_type( ) } | Rp { calculate_salary( ) }|.
  ENDMETHOD.

  METHOD get_employee_type. rv_type = 'Employee'. ENDMETHOD.
ENDCLASS.

CLASS lcl_permanent DEFINITION INHERITING FROM lcl_employee.
  PUBLIC SECTION.
    DATA: mv_bonus_pct TYPE p LENGTH 4 DECIMALS 2.
    METHODS: constructor
               IMPORTING iv_emp_id   TYPE string
                         iv_name     TYPE string
                         iv_base_pay TYPE p
                         iv_bonus    TYPE p DEFAULT '0.10',
             calculate_salary REDEFINITION.
  PROTECTED SECTION.
    METHODS: get_employee_type REDEFINITION.
ENDCLASS.

CLASS lcl_permanent IMPLEMENTATION.
  METHOD constructor.
    super->constructor( iv_emp_id = iv_emp_id
                        iv_name = iv_name
                        iv_base_pay = iv_base_pay ).
    mv_bonus_pct = iv_bonus.
  ENDMETHOD.

  METHOD calculate_salary.
    rv_salary = mv_base_pay + ( mv_base_pay * mv_bonus_pct ).
    gv_total_payroll = gv_total_payroll + rv_salary.
    RAISE EVENT salary_calculated
      EXPORTING ev_emp_id = mv_emp_id ev_amount = rv_salary.
  ENDMETHOD.

  METHOD get_employee_type. rv_type = 'Permanent'. ENDMETHOD.
ENDCLASS.

*----------------------------------------------------------------------*
* EVENT HANDLER: Audit Logger
*----------------------------------------------------------------------*
CLASS lcl_audit_logger DEFINITION.
  PUBLIC SECTION.
    METHODS: on_salary_calculated
               FOR EVENT salary_calculated OF lcl_employee
               IMPORTING ev_emp_id ev_amount.
ENDCLASS.

CLASS lcl_audit_logger IMPLEMENTATION.
  METHOD on_salary_calculated.
    WRITE: / |AUDIT: Gaji { ev_emp_id } = Rp { ev_amount } dicatat.|.
  ENDMETHOD.
ENDCLASS.

*----------------------------------------------------------------------*
* MAIN PROGRAM
*----------------------------------------------------------------------*
START-OF-SELECTION.

  lcl_employee=>gv_total_employees = 0.
  lcl_employee=>gv_total_payroll   = 0.

  DATA: lt_employees TYPE TABLE OF REF TO lcl_employee.

  APPEND NEW lcl_permanent( iv_emp_id = 'EMP-001'
    iv_name = 'Ahmad Fauzi'
    iv_base_pay = 10000000 ) TO lt_employees.

  APPEND NEW lcl_permanent( iv_emp_id = 'EMP-002'
    iv_name = 'Siti Rahayu'
    iv_base_pay = 12000000 ) TO lt_employees.

  APPEND NEW lcl_contract( iv_emp_id = 'CTR-001'
    iv_name = 'Budi Santoso'
    iv_base_pay = 7000000 ) TO lt_employees.

  APPEND NEW lcl_intern( iv_emp_id = 'INT-001'
    iv_name = 'Rizki Pratama'
    iv_base_pay = 4000000 ) TO lt_employees.

  " Setup event listener
  DATA(lo_logger) = NEW lcl_audit_logger( ).
  LOOP AT lt_employees INTO DATA(lo_emp).
    SET HANDLER lo_logger->on_salary_calculated FOR lo_emp.
  ENDLOOP.

  " ═══ CETAK PAYSLIP (Polymorphism) ═══
  LOOP AT lt_employees INTO lo_emp.
    WRITE: / lo_emp->get_payslip( ).
  ENDLOOP.

  " ═══ COMPANY SUMMARY (Static Members) ═══
  WRITE: / |Total Karyawan : { lcl_employee=>gv_total_employees }|.
  WRITE: / |Total Payroll  : Rp { lcl_employee=>gv_total_payroll }|.

" ═══ Output yang diharapkan: ═══
" AUDIT: Gaji EMP-001 = Rp 11000000.00 dicatat.
" AUDIT: Gaji EMP-002 = Rp 13200000.00 dicatat.
" AUDIT: Gaji CTR-001 = Rp 7000000.00  dicatat.
" AUDIT: Gaji INT-001 = Rp 1600000.00  dicatat.
" ═══════════════════════════════
"   PAYSLIP — Permanent
"   ID    : EMP-001
"   Nama  : Ahmad Fauzi
"   Gaji  : Rp 11000000.00
" ═══════════════════════════════
" ... (dst untuk semua karyawan)
